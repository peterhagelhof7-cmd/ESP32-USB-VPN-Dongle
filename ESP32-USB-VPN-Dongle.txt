# ESP32-USB-VPN-Dongle – erweiterte Projektbeschreibung

## 1. Projektziel

Entwicklung eines kleinen USB-Geräts auf Basis des **ESP32-S2 oder S3**, das sich gegenüber Windows und macOS als **USB-Netzwerkadapter** präsentiert.

Der Benutzer steckt den ESP32-S2 per USB an den Rechner. Das Betriebssystem erkennt ihn als Netzwerkgerät. Anschließend öffnet sich möglichst automatisch die Konfigurationsseite des ESP32 über die **Captive-Portal-/„Netzwerk erfordert Anmeldung“-Funktion**.

Der Benutzer muss keine IP-Adresse kennen und zunächst auch keinen Treiber oder WireGuard-Client installieren.

Das Gerät übernimmt:

* USB-NCM-Netzwerkadapter
* WLAN-Client
* DHCP
* DNS
* Captive Portal
* NAT/Routing
* WireGuard
* Firewall
* Kill Switch
* Webinterface
* RDP-/Ressourcenverwaltung

# 3. USB-NCM

Der ESP32-S2 verwendet seine native USB-Schnittstelle.

Gegenüber dem Computer erscheint er als:

> USB Network Adapter

Ziel ist die Verwendung von **USB NCM**, sodass möglichst kein eigener ESP32-Treiber installiert werden muss.

```text
Windows / macOS
       │
       │ USB-C
       ▼
ESP32-S2 Mini
       │
       ▼
USB-NCM
```

Der ESP32 stellt dabei ein eigenes kleines Netzwerk bereit.

Beispiel:

```text
ESP32:
192.168.226.1
DHCP Range nur 8 Hosts, entsprechend kleine netzmaske wählen, DHCP Lease Zeit 10min

PC:
192.168.226.2

```

---

# 4. Captive Portal / automatische Webseitenerkennung

Eine zentrale Funktion des Projekts ist die Nutzung der Betriebssystemfunktion:

> **„Netzwerk erfordert Anmeldung“**

bzw. des Captive-Portals.

Nach dem USB-Anschluss soll das Betriebssystem erkennen, dass das USB-Netzwerk zunächst eine Webkonfiguration benötigt.

Der ESP32 stellt dafür:

* DHCP
* DNS
* HTTP
* Captive-Portal-Erkennung

bereit.

### Ablauf

```text
PC
 │
 │ DHCP
 ▼
ESP32
 │
 ├── IP-Adresse
 ├── Gateway
 └── DNS
```

Windows/macOS führt anschließend seine normale Netzwerk-/Connectivity-Prüfung durch.

Der ESP32 beantwortet diese Anfragen so, dass das Betriebssystem erkennt:

> Netzwerk erfordert Anmeldung

Daraufhin kann das Betriebssystem dem Benutzer die Webanmeldung anbieten.


Der Benutzer soll diese Adresse aber normalerweise **nicht kennen müssen**.

```text
┌───────────────────────────────┐
│        ESP32 USB VPN          │
├───────────────────────────────┤
│ WLAN auswählen                │

│ ○ Gast-WLAN                   │
│                               │
│ Passwort: [**************]    │
│                               │

└───────────────────────────────┘
```

Erlaubt:

* WLAN-Scan
* WLAN auswählen

* WireGuard-Konfiguration anzeigen

* Firewall verändern
* RDP-Ziele verändern
* Firmware ändern
* OTA Update
* Datei Upload

# 9. WLAN

Der ESP32 arbeitet als **WLAN-Client**.

Der Benutzer kann:

* WLAN scannen
* SSID auswählen
* Passwort eingeben
* Verbindung testen
* gespeichertes WLAN ändern
* WLAN-Verbindung trennen
* Betriebsmodus Wahl (alles durch die VPN/ VPN nur geroutet)

Optional können mehrere WLAN-Profile gespeichert werden.

Beispielsweise:

```text
1. Büro
2. Zuhause
3. Handy

es Muss eine Checkbox "automatisch verbinden wenn in reichweite" geben.
```

Der ESP kann automatisch das bevorzugte verfügbare WLAN auswählen.

---

# 10. WireGuard

Der ESP32 baut den WireGuard-Tunnel selbst auf.

Eine normale WireGuard-Konfigurationsdatei kann importiert werden.

```ini
[Interface]
PrivateKey = ...
Address = 10.10.0.2/24
DNS = 10.10.0.1
PSK Optional

[Peer]
PublicKey = ...
Endpoint = vpn.example.de:51820
AllowedIPs = 10.10.0.0/24
PersistentKeepalive = 25
```

Der Private Key wird geschützt gespeichert und nicht im normalen Webinterface angezeigt.

---

# 11. Split Tunnel

Es sollen gezielt interne Netzwerke über WireGuard erreichbar sein.

Beispiel:

```text
10.10.0.0/24
192.168.100.0/24
172.16.20.0/24

```

Routing:

```text
Windows
   │
   ├── Internet ─────────────► WLAN
   │
   ├── 10.10.0.0/24 ────────► WireGuard
   │
   ├── 192.168.100.0/24 ────► WireGuard
   │
   └── 172.16.20.0/24 ──────► WireGuard
```
der DHCP server gibt gezielt DHCP Classless Static Routes (Option 121) für die VPN Netzwerke aus
---

# 12. Full Tunnel

Optional kann sämtlicher Datenverkehr über WireGuard laufen.

```text
Windows
   │
   ▼
ESP32
   │
   ▼
WireGuard
   │
   ▼
VPN-Server
   │
   ▼
Internet
```
der DHCP server gibt gezielt DHCP Classless Static Routes (Option 121) für die 0.0.0.0/0 Netzwerk aus


Damit kann der ESP32 als vollständiger VPN-Router arbeiten.

# 13. Kill Switch

Der Kill Switch verhindert einen VPN-Leak.

### VPN aktiv

```text
USB
 │
 ▼
ESP32
 │
 ▼
WireGuard 🟢
 │
 ▼
Internet
```

### VPN ausgefallen

```text
USB
 │
 ▼
ESP32
 │
 ▼
WireGuard 🔴
 │
 X
Internet
```

Der Zugriff auf das lokale ESP-Webinterface bleibt weiterhin möglich.

# 14. NAT und Routing

Der ESP32 arbeitet als Router zwischen USB und WLAN/WireGuard.

```text
             ESP32-S2
        ┌─────────────────┐
        │                 │
USB ───►│ Routing + NAT   │
        │       │         │
        │       ▼         │
        │ WireGuard       │
        │       │         │
        │       ▼         │
        │ WLAN            │
        └─────────────────┘
```

Damit muss Windows nichts über das dahinterliegende WLAN oder VPN wissen.

# 22. Automatischer Verbindungsaufbau

Nach der Erstkonfiguration:

```text
USB einstecken
      ↓
ESP32 bootet
      ↓
WLAN verbinden
      ↓
Internet prüfen
      ↓
WireGuard starten
      ↓
Handshake prüfen
      ↓
Routing aktivieren
      ↓
USB-Netzwerk freigeben
```

Bei einem VPN-Ausfall:

```text
VPN verloren
     ↓
Traffic blockieren
     ↓
WireGuard neu verbinden
     ↓
Handshake erfolgreich
     ↓
Traffic wieder freigeben
```

# 27. Endgültiges Konzept

Das fertige Gerät ist ein kleiner:

## **ESP32-S2 USB VPN Gateway**

Der Benutzer benötigt lediglich:

**USB-Kabel + WLAN**

Das Gerät übernimmt:

```text
             ┌──────────────────────┐
             │     ESP32-S2 Mini    │
             │                      │
PC/Mac ◄────►│ USB-NCM              │
             │                      │
             │ DHCP                 │
             │ DNS                  │
             │ Captive Portal       │
             │ Webinterface         │
             │ NAT                  │
             │ Firewall             │
             │ WireGuard            │
             │ Kill Switch          │
             │ RDP Manager          │
             │                      │
             │ WLAN                 │
             └──────────┬───────────┘
                        │
                        ▼
                     WLAN
                        │
                        ▼
                   Internet
                        │
                        ▼
                 WireGuard Server
                        │
                        ▼
                internes Netzwerk
```

### Das besondere Merkmal

**Der Rechner muss nichts über VPN wissen.**

Er sieht nur:

> **USB-Netzwerkadapter**

Die gesamte VPN- und Routing-Funktion steckt im ESP32.

Zusätzlich sorgt das **Captive Portal** dafür, dass der Benutzer nach dem Einstecken möglichst automatisch zur Konfigurationsseite geführt wird.

Damit entsteht aus dem ursprünglichen ESP32-S2-Projekt ein **kleiner, portabler Plug-and-Play-VPN-Gateway**, der insbesondere für Wartung, Remote-Arbeit und den Zugriff auf abgeschottete interne Netzwerke interessant ist.
erwartete Wlan Performance 10Mbits
erwartete VPN Performance 5Mbits
